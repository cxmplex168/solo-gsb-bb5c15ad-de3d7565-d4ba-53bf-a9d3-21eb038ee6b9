# 食品过敏原标签审查台

基于 **FastAPI + SQLite** 的食品过敏原标签审查工具：在浏览器中录入带嵌套子配料的配方文本和原料过敏原字典，系统自动解析括号层级、沿配料树传播并汇总每种原料的过敏原集合，与标签声明比对指出**遗漏 / 多报**的过敏原；支持录入**两版配方**查看过敏原变化，并可一键导出标签审查报告（HTML / Markdown）。

## 功能一览

- 🌳 **嵌套配方解析**：`巧克力酱（可可脂，奶粉（乳清粉，乳糖））` 多层括号任意嵌套，中英文括号均可
- 🧬 **过敏原传播**：子配料的过敏原自动向上传播到父级配料，逐层汇总
- 🔎 **遗漏来源追踪**：每个遗漏过敏原保留其在嵌套配料树中的全部来源路径（如 `巧克力酱 › 奶粉 › 乳清粉`），同名原料出现在不同分支时路径分别保留、稳定去重排序；结果页可逐项展开，HTML / Markdown 报告同步输出，升级前的历史记录重新打开时也会自动补齐
- ✅ **标签核对**：对照标签声明的过敏原，标出「遗漏（必须补充）」「多报」「一致」
- 🔄 **版本对比**：录入现版 / 新版两版配方，输出新增、减少的过敏原及每种配料的变化
- 📄 **报告导出**：HTML（可直接打印存档）与 Markdown 两种格式
- 📚 **字典管理**：原料 → 过敏原字典批量导入、逐条增删，未登记原料自动提示
- 🔗 **原料别名管理**：按 `别名：标准名` 批量维护，支持任意长度链（如 `脱盐乳清：乳清粉`、`乳清粉：奶粉`）；导入时把映射当作**有向图整批原子校验**，自环、任意长度环、同一别名多目标一律整批拒绝，错误返回冲突行，环额外返回从最早冲突行展开的**最短环路**。审查时合法别名链解析到**最终标准名**再参与字典查询与指纹计算，而配方树、遗漏来源路径仍显示原料原始名称。别名**仅接入正式审查与字典时效复核**（不影响两个临时预览）；别名规则变化后，历史记录仅在其实际原料的最终标准名或对应过敏原映射改变时才标记「需复核」
- 🕰️ **字典时效复核**：每次审查保存所用字典（仅针对配方实际涉及原料，并按别名解析到最终标准名）的稳定指纹；字典增删 / 批量导入或别名变更后，仅当相关原料的最终标准名 / 映射发生变化时历史记录才标出「需复核」，顺序调整、无关原料或无关别名变化、等价链路改写不会误报；详情页可一键复核，先展示遗漏 / 多报 / 来源路径的前后差异，确认后覆盖结果并更新指纹
- 🧪 **供应商方案风险区间（临时预览）**：为配方中的若干原料输入互斥过敏原方案（`原料：方案1；方案2`，方案内逗号分隔，空方案写「无」），未覆盖原料沿用字典；后端不枚举方案组合，而在嵌套配料树上分别传播**必然过敏原（各方案交集）**与**可能过敏原（各方案并集）**，据标签声明给出确定遗漏 / 潜在遗漏 / 确定多报 / 潜在多报，两类遗漏均附来源路径；所有覆盖原料只有一个方案时结果与正式审查一致。预览只读，不写入字典或历史记录
- 📐 **配料占比区间顺序校验（临时预览）**：在嵌套配方的每个原料名后标注占比区间（`奶粉[8-12%]`，单值写 `食盐[2%]`），按标签顺序对每组同级配料建立**占比非递增**约束；后端用**区间传播**（前向收紧上界、后向收紧下界）而非组合枚举判断整组可行性：可行时给出每项收紧后的精确可行区间并标出只能取单一边界值的项，不可行时返回**最短冲突片段**及完整嵌套路径；缺少区间、格式错误、负值、下界大于上界均逐条定位到具体路径。预览只读，不写入审查历史
- 🏭 **共线生产换线排程（临时预览）**：把历史审查记录当作共线产品，复用各记录**当前配方**（两版记录取标签核对对象，即新版配方）的**最终过敏原集合**；勾选 2～10 个产品并为各过敏原配置清洁分钟数，按「前一产品含有、后一产品不含」计算**有向换线成本**，用**子集动态规划**（Held-Karp）求总清洁时间最短的完整生产顺序，并列时按**产品 ID 序列**取最小并统计并列数量；逐段展示需清洁过敏原、耗时与累计耗时；缺失或处于需复核状态的记录**禁止参与**并逐条指出原因。预览只读，不改写审查记录
- 🏷️ **共用标签模板分组（临时预览）**：复用历史审查记录**当前配方**（两版记录取标签核对对象，即新版配方）的**最终过敏原集合**；勾选 2～12 个时效正常产品并为每个产品设置**最多允许的附加声明数量**：一组产品共用一张标签模板（内容 = 组内过敏原**并集**），每个产品的附加声明为「模板有而自身没有」的过敏原，仅当组内每个产品的附加声明数都不超限时该组才成立；用**子集动态规划**求**模板数量最少**的完整分组，并列时按**组内及组间产品 ID 序列**取唯一最小者并统计并列方案数；逐组展示模板、成员与各产品附加声明；缺失或需复核记录**禁止参与**并逐条指出原因。预览只读，不改写审查记录
- 🧮 **目标过敏原最小改配方案（临时预览）**：从历史记录选择**一条时效正常**记录及目标过敏原，复用其**当前配方树**（两版取标签核对对象，即新版配方）列出该过敏原的**全部来源路径**（携带该过敏原的自身标注节点）；用户按**完整节点路径**填写可替换成本，**未填写节点视为不可替换**；后端在来源前缀候选树上用**树形动态规划**求覆盖全部来源路径的**最低总成本**节点集合——选择祖先即同时阻断其子树中的全部来源，方案不得再选其后代；同成本按**节点路径序列字典序**取最小并统计并列方案数；展示所选节点、各自阻断的来源与总成本；无解时逐条列出**仍不可覆盖的来源**（整条路径均未填写成本）。成本经精确有理数运算，并列判定不受浮点误差影响；记录缺失或需复核时**禁止选择**。预览只读，不改写审查记录
- 🧪 **过敏原检测套餐规划（临时预览）**：从历史记录中**仅选择一条时效正常**记录，读取其**当前配方**（两版记录取标签核对对象，即新版配方）的**最终过敏原**作为套餐组合**必须覆盖项**；逐行录入 `套餐名：价格：过敏原列表`（冒号中英文均可，`#` 注释 / 空行忽略，套餐名不可重复，过敏原列表可空）；后端以**精确小数**（`Fraction(str(...))`，`0.1 + 0.2` 与 `0.3` 判同价）解析价格，用**子集动态规划**（覆盖状态 2^|过敏原|）求**总价最低**的套餐组合（每个套餐至多选一次，套餐含有的非目标过敏原不影响可行性）；同价按**套餐名升序序列字典序**展示唯一方案并统计并列组合数；逐套餐展示**覆盖贡献**（本套餐新覆盖的必须项）、**累计覆盖**与额外过敏原；任何组合都无法覆盖时逐条列出**覆盖缺口**；不覆盖任何必须项的套餐原样列出但不参与组合。记录缺失（已删除）、ID 无效或转为**需复核**时接口拒绝并在 `detail.problems` 逐条说明；套餐行格式 / 价格 / 重名问题整批拒绝、逐行定位。预览只读，套餐与审查记录均不写库
- 🔬 **池化检测阳性溯源（临时预览）**：从历史记录中**仅选择一条时效正常**记录，读取其**当前配方**（两版记录取标签核对对象，即新版配方）配料树的**叶子原料**（无子配料节点，同名折叠并记录出现次数与路径）作为检测池允许引用的原料全集；逐行录入 `池名：原料列表：阳性/阴性`（冒号中英文均可，`#` 注释 / 空行忽略，池名不可重复，状态只接受精确的「阳性 / 阴性」）；**阴性池排除其全部原料**，**阳性池**须至少含一个未被排除的嫌疑原料，否则返回**无解**与冲突池（并给出每种原料被哪些阴性池排除）；后端用**子集动态规划**（命中集 / set cover，状态 2^|阳性池|）求解释全部阳性结果的**最少嫌疑原料集合**，统计全部并列解并按**原料名升序序列字典序**展示唯一最小解，逐个列出嫌疑原料**解释的阳性池**，并回显每个阳性池的命中嫌疑与阴性池排除关系；池引用**非配方叶子原料**、池名重名或状态非法时**整批拒绝**并定位到行。记录缺失（已删除）、ID 无效或转为**需复核**时接口拒绝并在 `detail.problems` 逐条说明。预览只读，检测池与审查记录均不写库
- 💾 **持久化**：SQLite 存储字典与全部历史审查记录，可随时回看、重新导出
- 📦 **审查数据迁移包**：一键导出全量 JSON 迁移包（字典 + 别名 + 审查记录 + 格式版本 + 按规范化内容计算的 SHA-256，同一数据库重复导出内容稳定）；导入前先**只读预检**，逐项校验版本 / 摘要 / 字段类型 / 别名图无环 / 审查记录结构（不写库），通过后凭**绑定文件摘要的一次性令牌**确认，在**单个 SQLite 事务**内整体替换，任一步失败整体回滚；每次成功替换前在**同一事务**内把当前字典 / 别名 / 审查记录保存为**最新恢复点**（含时间、三类数量与内容摘要，替换失败不产生恢复点），迁移区展示恢复点并支持**输入摘要二次确认后一键恢复**——恢复时先把当前数据交换成新的恢复点，误恢复可再次撤回；并发确认最多一次生效

## 快速开始

### 方式一：Docker Compose（推荐）

单条命令即可启动完整应用（含数据迁移包功能，无需额外服务）：

```bash
docker compose up --build
```

### 方式二：Docker

```bash
docker build -t allergen-review .
docker run -d -p 8000:8000 -v $(pwd)/data:/app/data allergen-review
```

### 方式三：本地运行

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

三种方式启动后，均在浏览器访问 **<http://localhost:8000>** 进入 Web 界面（入口端口 **8000**；交互式 API 文档见 <http://localhost:8000/docs>）。

## 端口与访问

| 项目 | 地址 |
| --- | --- |
| Web 界面 | <http://localhost:8000> |
| API 文档（Swagger） | <http://localhost:8000/docs> |
| 端口 | **8000**（宿主机端口可在 `docker-compose.yml` 的 `ports` 中修改） |

SQLite 数据库文件位于 `./data/app.db`（Compose 已挂载该目录，容器重启数据不丢失）；可用环境变量 `DB_PATH` 覆盖路径。

## 使用说明

1. **导入过敏原字典**：每行一条，格式 `原料名：过敏原1，过敏原2`（冒号、逗号中英文均可），例如：

   ```text
   小麦粉：麸质谷物
   乳清粉：乳
   大豆卵磷脂：大豆
   可可脂：
   ```

2. **维护原料别名（可选）**：在「② 原料别名」区每行一条 `别名：标准名`（冒号中英文均可，`#` 注释、空行忽略），可成链：

   ```text
   脱盐乳清：乳清粉
   浓缩乳清蛋白：乳清粉
   whey powder：乳清粉
   ```

   - 整批做有向图原子校验，任何一条有问题都**整批不写入**：自环（`奶粉：奶粉`）、任意长度环（`甲：乙、乙：丙、丙：甲`）、同一别名指向多个标准名都会被拒绝，错误逐条给出冲突行，环给出从最早冲突行展开的最短环路（如 `甲 → 乙 → 丙 → 甲`）；同别名同目标重复行会幂等折叠。
   - 正式审查时每种原料沿别名链解析到**最终标准名**再查字典、判定未识别并参与指纹；配方解析树与遗漏来源路径始终显示**原始名称**（如配方写「脱盐乳清」，树和路径里仍是「脱盐乳清」，但按「乳清粉」取到「乳」）。
   - 「解析预览（按下方配方 A）」可在不创建审查的情况下查看每种原料的解析链、最终标准名及其字典过敏原。
   - 别名仅用于正式审查与字典时效复核；供应商方案、占比校验两个临时预览不应用别名。

3. **录入配方**：配料用逗号分隔，括号表示子配料，可多层嵌套；`配料表：` 等前缀会自动去除：

   ```text
   配料表：小麦粉，白砂糖，巧克力酱（可可脂，奶粉（乳清粉，乳糖），大豆卵磷脂），鸡蛋，食盐
   ```

4. **勾选标签声明的过敏原**，点击「开始审查」，即可看到：
   - 标签核对结论（遗漏 / 多报 / 一致）；
   - 配方解析树，深绿色徽章为原料自身标注，浅色徽章为子配料传播结果；
   - 填写配方 B 时，额外展示两版过敏原差异与每种配料的变化。
5. **导出报告**：结果页或历史记录中下载 HTML / Markdown 审查报告。
6. **字典时效复核**：
   - 每次新建审查时，系统保存一份**仅包含该记录 A/B 配方实际涉及原料**（按当前别名规则解析到最终标准名）的字典稳定指纹（标准名与过敏原均排序后哈希），历史列表的「字典时效」列显示 **时效正常 / 需复核**。
   - 字典逐条增删 / 批量导入或别名变更后，历史列表自动刷新。只有当**记录配方实际涉及原料的最终标准名、或其过敏原映射**发生变化（过敏原增删、相关条目删除、为原先未登记的原料补登记、别名改写指向不同标准名）时才会标出「需复核」；字典条目顺序调整、配方未涉及原料的变化、相同内容重复导入、仅改写等价别名链（最终标准名与映射不变）、无关别名增删均**不会误报**。
   - 在历史列表点「一键复核」或打开记录详情后，系统用**当前字典与别名规则重新解析原始 A/B 配方与标签声明**，先展示标签遗漏 / 多报、各遗漏过敏原**来源路径**以及两版过敏原、未识别原料的**前后差异**；可展开「查看复核后结果」预览完整新结论。
   - 点击「确认并覆盖结果」后，新结果覆盖旧记录、指纹同步更新，状态恢复为时效正常；确认前的预览不会改动任何数据。差异为空时确认仅会刷新指纹。
   - 升级前产生的旧记录没有指纹，会标记为「需复核（旧记录）」，按上述流程**按需复核**一次即可补上指纹。
7. **供应商方案风险区间（临时预览）**：
   - 在「④ 供应商方案风险区间」区录入配方、互斥方案与标签声明，点击「预览风险区间」。每行一条 `原料：方案1；方案2`，方案之间用分号分隔（中英文均可），方案内用逗号 / 顿号分隔过敏原；恰好为「无」的方案表示该方案下原料不含过敏原（覆盖字典，不算未识别）；未覆盖原料沿用当前字典（**不应用别名**）。
   - 后端**不枚举方案组合**：互斥方案只作用于单个原料节点，每个配料节点同时维护「必然（各方案交集）」「可能（各方案并集）」两个集合，按与正式审查相同的规则沿嵌套树向上传播。
   - 结果分为：**确定遗漏**（必然含有且未声明，红色徽章，附来源路径）、**潜在遗漏**（仅部分方案可能含有且未声明，橙色虚框徽章，附来源路径）、**确定多报**（任何方案都不可能含有）、**潜在多报**（仅部分方案可能引入）、**一致**（必然含有且已声明）。
   - 配料树中深绿色徽章 = 自身必然含有；黄色虚框徽章 = 自身仅部分方案可能含有；`◈ 方案×n` 标记被方案覆盖、不使用字典的原料。若方案原料未在配方中出现，会提示「未使用」。
   - 当被覆盖原料均只有一个方案（或没有任何方案）时，`必然 == 可能`，风险预览与现有标签审查口径完全一致，页面以绿色「单方案 · 与正式审查一致」标记提示。
   - 该能力**仅做临时预览**：不写入过敏原字典，不生成历史审查记录，刷新即失效；「填充风险示例」可快速体验。
8. **配料占比区间顺序校验（临时预览）**：
   - 在「⑤ 配料占比区间顺序校验」区录入带占比标注的配方，点击「校验占比顺序」。每个原料名后必须有占比标注：区间写 `奶粉[8-12%]`，单值写 `食盐[2%]`；父配料先标注再跟子配料括号，如 `巧克力酱[25-60%]（可可脂[10-18%]，奶粉[12-15%]）`。
   - 校验规则：每组同级配料（顶层为一组，每个父配料的子配料各为一组）按标签书写顺序须满足占比非递增。后端**不做组合枚举**，而是区间传播：前向 `H_i = min(hi_1..hi_i)`、后向 `L_i = max(lo_i..lo_n)`，整组可行当且仅当所有 `L_i ≤ H_i`。
   - 可行时展示每项收紧后的精确可行区间（链式约束下传播完备，区间内任意取值都能扩展为整组可行赋值），被锁定为单值的项以「锁定单值」标出；不可行时给出每组的最短冲突片段（跨度最小的冲突区间对，其间的连续片段）及完整嵌套路径。
   - 缺少区间、格式错误、负值、下界大于上界时，逐条列出并定位到具体嵌套路径，全部修正后再校验。
   - 该能力**仅做临时预览**：不写入审查历史，刷新即失效；「填充占比示例」可快速体验区间收紧与单值锁定。
9. **共线生产换线排程（临时预览）**：
   - 在「⑥ 共线生产换线排程」区勾选 2～10 个产品（每条历史审查记录即一个产品），系统复用各记录**当前配方**（两版记录取标签核对对象，即新版配方）的最终过敏原集合，列表同时展示取值版本与参与资格。
   - 勾选后按所选产品的过敏原并集生成清洁分钟数输入框（预填 30 分钟，可逐个修改；未配置的过敏原按 0 分钟计），点击「计算最优换线顺序」。
   - 换线成本是**有向**的：前一产品 → 后一产品需清洁「前者含有、后者不含」的过敏原，成本为其清洁分钟数之和；后端用**子集动态规划**（Held-Karp）求总清洁时间最短的完整生产顺序（每个产品恰好生产一次，首产产品无换线成本），总耗时并列时按**产品 ID 序列**取最小者，并提示并列最优顺序的总数；分钟数经精确有理数运算，并列判定不受浮点误差影响。
   - 结果逐段展示：每段需清洁的过敏原（含各自分钟数）、本段耗时与累计耗时，以及最优顺序与总清洁时间。
   - 记录缺失（不存在 / 已删除）或处于**需复核**状态时**禁止参与**：列表中相应记录不可勾选并附原因，接口被调用时也会拒绝并逐条指出原因；先在「⑪ 历史审查记录」完成字典时效复核即可恢复参与。
   - 该能力**仅做临时预览**：不写入字典，不改写任何审查记录，刷新即失效。
10. **共用标签模板分组（临时预览）**：
   - 在「⑦ 共用标签模板分组」区勾选 2～12 个产品（每条历史审查记录即一个产品），系统复用各记录**当前配方**（两版记录取标签核对对象，即新版配方）的最终过敏原集合，列表同时展示取值版本与参与资格。
   - 勾选后为每个所选产品生成「最多允许的附加声明数量」输入框（预填 1 个，可逐个修改；未填写按 0 个计），点击「计算最少模板分组」。
   - 一组产品共用一张标签模板：模板内容 = 组内产品过敏原**并集**；每个产品的**附加声明**为「模板含有而自身没有」的过敏原，仅当组内每个产品的附加声明数都不超过其上限时该组才成立（单个产品总是成组）。后端用**子集动态规划**求**模板数量最少**的完整分组（每个产品恰好归入一组），模板数并列时按**组内及组间产品 ID 序列**取唯一最小者，并提示达到最少模板数的分组方案总数。
   - 结果逐组展示：模板内容（并集）、成员清单及每个产品的附加声明与「附加数 / 上限」。
   - 记录缺失（不存在 / 已删除）或处于**需复核**状态时**禁止参与**：列表中相应记录不可勾选并附原因，接口被调用时也会拒绝并逐条指出原因；先在「⑪ 历史审查记录」完成字典时效复核即可恢复参与。
   - 该能力**仅做临时预览**：不写入字典，不改写任何审查记录，刷新即失效。
11. **目标过敏原最小改配方案（临时预览）**：
   - 在「⑧ 目标过敏原最小改配方案」区从历史记录中单选 **1 条时效正常**的记录，再选择一个目标过敏原，点击「载入来源路径」。系统复用该记录**当前配方**（两版记录取标签核对对象，即新版配方）的配方树，列出目标过敏原的全部来源路径（每个**自身标注**携带该过敏原的节点一条路径，如 `巧克力酱 › 奶粉 › 乳清粉`）。
   - 来源路径上的每个节点都是候选替换点，按**完整节点路径**为可替换的配料填写替换成本（金额/工时等任意同口径单位均可），**留空表示该节点不可替换**。
   - 点击「计算最小改配方案」，后端在候选树上做**树形动态规划**：选择某个节点即同时**阻断其子树**中的全部来源，方案中不会再选它的任何后代；输出覆盖全部来源路径的**最低总成本**节点集合，并逐节点展示其替换成本与**各自阻断的来源清单**。
   - 总成本并列时按所选节点**完整路径序列的字典序**展示唯一最小者，并提示并列最优方案总数；成本经精确有理数运算，`0.1 + 0.2` 与 `0.3` 等情形不会因浮点误差漏判并列。
   - 若某条来源路径上的所有节点（含来源节点自身与各祖先）都未填写成本，该来源不可能被覆盖：结果区标注**无可行改配方案**并逐条列出仍不可覆盖的来源路径，补齐其中至少一个节点的成本后重新计算即可。
   - 记录缺失或处于**需复核**状态时**禁止选择**：列表中相应记录不可选并附原因，接口被调用时也会拒绝并逐条指出原因；先在「⑪ 历史审查记录」完成字典时效复核即可恢复。
   - 该能力**仅做临时预览**：不写入字典，不改写任何审查记录，刷新即失效。
12. **过敏原检测套餐规划（临时预览）**：
   - 在「⑨ 过敏原检测套餐规划」区从历史记录中**单选 1 条时效正常**的记录，系统读取该记录**当前配方**（两版记录取标签核对对象，即新版配方）的最终过敏原，作为套餐组合的**必须覆盖项**并以红色徽章列出。
   - 在文本框逐行录入候选套餐，格式 `套餐名：价格：过敏原列表`，例如：

     ```text
     基础套餐：9.90：麸质谷物，蛋类
     乳品专项：10.00：乳
     尊享全包：30.00：麸质谷物，乳，大豆，蛋类，坚果，芝麻
     ```

     冒号中英文均可且必须恰好两段（三列）；过敏原之间用逗号 / 顿号 / 分号 / 空白分隔，也可留空（该套餐不覆盖任何必须项，仅原样列回，不参与组合）；价格必须是不小于 0 的数字；`#` 开头的行与空行忽略；同一批内套餐名必须唯一。格式错误、价格非法或重名时**整批拒绝**并逐行给出原因（标注行号）。
   - 点击「计算最低总价套餐组合」，后端把价格按字符串解析为精确有理数（`0.1 + 0.2` 与 `0.3` 视为同价，不受浮点误差影响），用**子集动态规划**（覆盖位掩码，每个套餐至多选一次）求**总价最低**且覆盖全部必须项的组合；套餐含有而配方最终集合中没有的过敏原作为**额外过敏原**原样展示，不影响可行性。不含任何必须项的套餐不参与组合，仅原样列回。
   - 结果先回显全部录入套餐（各自覆盖哪些必须项 / 含哪些额外过敏原），再按**套餐名升序序列**展示最优方案的每个套餐：**价格**、**本套餐覆盖贡献**（相对前面套餐新覆盖的必须项；允许为空，即该套餐覆盖的必须项均已被前面套餐覆盖）与**累计覆盖**（选到该套餐时已覆盖的必须项并集，空贡献时保持不变），并给出总价与套餐数；总价并列时提示并列组合总数，展示的方案为套餐名序列**字典序最小**的唯一者。**只要套餐覆盖至少一个必须项，即使加入当前组合后不再新增覆盖，0 元选择仍作为不同的最低价组合参与并列计数**（字典序最小时它会被展示，覆盖贡献为空）；正价格冗余套餐不可能更优，永不进入最低价。
   - 若没有任何套餐包含某些必须项，结果标注**无法覆盖**并逐条列出**覆盖缺口**，补齐对应套餐后重新计算即可；当前配方不含过敏原时，空组合即以 0 元完成覆盖。
   - 记录缺失（不存在 / 已删除）、ID 无效或处于**需复核**状态时接口拒绝并逐条说明原因（列表中相应记录也不可选）；先在「⑫ 历史审查记录」完成字典时效复核即可恢复。
   - 该能力**仅做临时预览**：套餐不入库，不新增也不改写任何审查记录，刷新即失效；「填充套餐示例」可快速体验。
13. **池化检测阳性溯源（临时预览）**：
   - 在「⑩ 池化检测阳性溯源」区从历史记录中**单选 1 条时效正常**的记录，系统读取该记录**当前配方**（两版记录取标签核对对象，即新版配方）配料树的**叶子原料**（没有子配料的原料；同名原料在配方多处出现时折叠为一种，徽章悬停可见出现次数），作为检测池**允许引用的原料全集**列出。
   - 在文本框逐行录入检测结果，格式 `池名：原料列表：阳性/阴性`，例如：

     ```text
     一号池：乳清粉，鸡蛋，大豆卵磷脂：阳性
     二号池：乳糖，鸡蛋，可可脂：阳性
     对照池：奶粉，可可脂，食盐：阴性
     ```

     冒号中英文均可且必须恰好两段（三列）；原料之间用逗号 / 顿号 / 分号 / 空白分隔；第三段状态只接受精确的「阳性」或「阴性」（`+` 之类简写视为非法）；`#` 开头的行与空行忽略；同一批内池名必须唯一；池内重复引用的原料自动折叠。**引用的每种原料都必须是该记录当前配方的叶子原料**，格式错误、状态非法、池名重名或引用非配方原料时**整批拒绝**并逐行给出原因（标注行号）。
   - 点击「求最少嫌疑原料集合」，后端先按**阴性池排除其全部原料**汇总阴性证据（同一原料被多个阴性池排除时逐一列出），再把每个阳性池视为一个必须被命中的目标：用**子集动态规划**（命中集 / set cover，每个候选原料至多选一次）求能解释全部阳性池的**最少嫌疑原料集合**，并统计达到最少原料数的**全部并列解**，按所选**原料名升序序列字典序**展示唯一最小者；结果逐个列出每个嫌疑原料**解释的阳性池**（包含该原料的阳性池，按录入顺序）与阳性池数，同时回显每个阳性池的命中嫌疑、排除后剩余候选与每个阴性池排除的原料。不出现在任何阳性池、或已被阴性排除的原料不参与求解。
   - 某阳性池的**全部原料都被阴性池排除**（或阳性池原料列表为空）时与阴性证据直接矛盾：结果标注**无可行嫌疑集合（无解）**，逐个列出**冲突池**、所在行、其原料分别被哪些阴性池排除，核对录入后重新计算即可。没有录入任何阳性池时，空集合（0 种原料）即唯一最少解。
   - 记录缺失（不存在 / 已删除）、ID 无效或处于**需复核**状态时接口拒绝并逐条说明原因（列表中相应记录也不可选）；先在「⑫ 历史审查记录」完成字典时效复核即可恢复。
   - 该能力**仅做临时预览**：检测池不入库，不新增也不改写任何审查记录，刷新即失效；「填充溯源示例」可快速体验。
14. **审查数据迁移包（备份 / 迁移）**：
   - **入口**：页面底部「⑬ 审查数据迁移包」区；对应 API 为 `GET /api/migration/export`、`POST /api/migration/precheck`、`POST /api/migration/import`、`GET /api/migration/restore-point`、`POST /api/migration/restore`。功能随主应用一键启动（`docker compose up --build` 单条命令），无需额外服务；恢复点保存在同一 SQLite 数据库（`./data/app.db`）内，持久化目录与启动方式完全兼容。
   - **导出**：点击「生成并下载迁移包」得到一个 JSON 文件，包含字典、原料别名、全部审查记录、格式版本号与按规范化内容（对象键排序的紧凑 JSON；过敏原 / 标签声明列表排序）计算的 SHA-256 摘要；同一数据库重复导出内容稳定（摘要一致），导入其他实例后再导出摘要也不变。页面同步展示包内数据量与摘要。
   - **预检（只读）**：选择文件后先点「只读预检」，后端逐项校验**格式版本、SHA-256 摘要、字段类型、别名图无环（含自环与归一化重复）、审查记录结构**，全部问题一次列出（定位到数据段与条目）且**不会写库**；通过时页面展示包内数据量、当前库数据量与**警告**（如将被替换的现有数据量、无指纹旧记录），并签发**绑定该文件摘要的一次性确认令牌**（10 分钟有效）。
   - **确认导入**：凭令牌确认后，在**单个 SQLite 事务**内**先把当前字典 / 别名 / 审查记录保存为最新恢复点**（含创建时间、三类数量与按规范化内容计算的 SHA-256 摘要；当前库为空时不产生），再整体替换三张表，任一步失败整体回滚——**替换失败不会生成恢复点**。令牌用后即废，更换文件、令牌过期或服务重启后需重新预检。确认导入 / 恢复共用进程级互斥锁，叠加令牌一次性，**并发确认最多一次生效**。导入完成后页面展示导入结果与新恢复点摘要并自动刷新全部页面数据。
   - **恢复点与一键恢复**：迁移区展示最新恢复点（产生时间、原因——确认导入前自动保存 / 恢复前交换保存、三类数量与内容摘要；始终只保留最新一个）。需**逐字输入该恢复点的 64 位 SHA-256 摘要二次确认**后才能一键恢复：恢复在单个事务内先校验摘要（不一致 / 恢复点内容损坏均拒绝且不写库），随后**先把当前数据交换保存为新的最新恢复点**（`reason=restore`），再用旧恢复点内容整体替换——因此**误恢复可再凭新摘要一键撤回**，可来回切换。恢复完成后自动刷新字典、别名、历史记录与恢复点全部页面数据。
   - ⚠ **备份提示**：恢复点是替换前自动留存的最近一份数据，可应对误导入；如需长期 / 离线备份，请在「⑬」区导出当前迁移包（或直接备份 `./data/app.db` 文件）。迁移包包含全部字典与审查记录明文，请妥善保管，不要提交到公开仓库。

页面上「填充示例」按钮可一键载入演示字典与两版配方，快速体验完整流程。

## 项目结构

```text
app/
├── main.py        # FastAPI 路由与审查流程编排（含别名、字典时效复核端点）
├── parser.py      # 嵌套括号配方解析（配料树）
├── aliases.py     # 原料别名：有向图整批原子校验（自环/环/多目标/最短环路）、链式解析与预览
├── analysis.py    # 过敏原传播（支持别名解析到标准名）、标签核对、版本差异
├── review.py      # 审查 / 复核共用的解析与结果构建（同时产出字典指纹）
├── fingerprint.py # 按配方涉及原料取子集、记录最终标准名的字典稳定指纹
├── recheck.py     # 用当前字典/别名重新解析并计算遗漏/多报/来源路径前后差异
├── supplier_risk.py # 供应商互斥方案：必然（交集）/可能（并集）树传播与风险区间预览
├── proportion.py  # 配料占比区间顺序校验：区间传播可行性判定、区间收紧与最短冲突片段定位
├── changeover.py  # 共线生产换线排程：有向换线成本、子集动态规划最优顺序与并列处理（只读）
├── template_group.py # 共用标签模板分组：并集模板、附加声明上限、子集 DP 最少模板分组与并列处理（只读）
├── reformulation.py # 目标过敏原最小改配方案：来源路径候选树、树形 DP 最低成本反链覆盖、字典序并列与无解来源（只读）
├── allergen_panel.py # 过敏原检测套餐规划：套餐行精确小数解析、子集 DP 最低总价覆盖、套餐名字典序并列与覆盖缺口（只读）
├── pool_trace.py    # 池化检测阳性溯源：当前配方叶子原料、阴性排除、阳性冲突、子集 DP 最少嫌疑命中集与原料名字典序并列（只读）
├── migration.py   # 审查数据迁移包：全量导出（规范化 SHA-256）、只读预检、一次性令牌确认导入（单事务先存恢复点再整体替换）、恢复点查询与摘要二次确认一键恢复（恢复交换可撤回、写操作互斥）
├── db.py          # SQLite 持久层（字典 + 原料别名 + 审查记录 + 指纹与时效判定 + 迁移包快照/整体替换/单行最新恢复点）
├── report.py      # HTML / Markdown 报告生成
└── static/
    └── index.html # 单页 Web 界面（含别名维护与解析预览、供应商风险、占比校验、换线排程、模板分组、最小改配方案、检测套餐规划、池化阳性溯源与数据迁移包）
tests/
├── test_core.py      # 解析与分析单元测试
├── test_aliases.py   # 别名有向图解析/原子校验/最短环路/链式解析/预览
├── test_alias_flow.py # 别名接入正式审查与时效复核的全链路（原名展示、误报边界、不接入风险预览）
├── test_persistence.py
├── test_recheck.py   # 字典指纹、失效判定与复核流程测试
├── test_supplier_risk.py # 互斥方案解析、交集/并集传播、五类结论与单方案一致性
├── test_proportion.py  # 占比标注解析、区间传播收紧、最短冲突片段与路径定位
├── test_changeover.py  # 换线排程：当前配方过敏原复用、有向成本、子集 DP 与并列、禁止参与、只读
├── test_template_group.py # 模板分组：并集模板、附加声明上限、子集 DP 与并列、禁止参与、只读
├── test_reformulation.py  # 最小改配：来源候选树、树形 DP 祖先阻断、字典序并列（对照暴力枚举）、无解、禁止选择、只读
├── test_allergen_panel.py # 套餐规划：行解析/精确小数、子集 DP 最低总价（对照暴力枚举）、套餐名字典序并列、覆盖缺口、禁止选择、只读

docker-compose.yml
requirements.txt
```
